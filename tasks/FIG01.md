# FIG01 论文示意图用的真实帧（只读导出，不渲染、不用 GPU）

**目标**：从训练场景的 Look→Flip 世界对的视角表里，导出智能体实际看到的画面，给 teaser 和方法总览图用。图由人类和另一个 Claude 窗口排版。
**优先级**：低于试跑、测试集和训练池。T0、T4 两个试跑都开跑之后再做。
**算力**：只读已有视角表，在登录节点完成；预计几分钟。超过 5 分钟就停下报告，不要为此提交 GPU 作业。

## 1. 选对
- 只从训练场景（FloorPlan1–20、201–220、301–320、401–420）中、已通过 T02 检查和缓存复核的 Look→Flip 对里选。**不用测试场景**（x21–x30）。T04 §1 的留出场景可以用，但优先非留出场景。
- 排序依据：第一次看到锚点 X 的那个状态里，X 的实例掩码像素数。从大到小取前 5 对作为候选。

## 2. 每对导出的内容
全部来自视角表里已有的字节：不重新渲染，不缩放，不改色。
- **s0**：智能体实际输入（带候选标号）一张。标号必须由查表环境本身生成，也就是训练时喂给模型的同一个函数，不另写画标号的代码。同时记录 w0、w1 两个世界 s0 图像字节的 SHA-256，两者应完全相同。
- **w0、w1 各自 turn_left、turn_right 之后的状态**：智能体实际输入（带标号）各一张，共 4 张。
- 上面 5 个状态的**无标号原始 RGB**（视角表里有就导出）。
- 这些状态里锚点 X、候选 A、候选 B 的**实例掩码**（二值 PNG）。
- `manifest.json`，包含：
  - pair_id、场景、房间类型、类别；
  - 锚点和两个候选的物体类别名；
  - 两个世界各自的正确目标；
  - 每张图对应的世界、状态编号和动作；
  - τ、τ_seen，以及每个状态里 X 的掩码像素数；
  - 源文件路径和 SHA-256，以及导出代码的 git commit。

## 3. 存放
- 仓库 `paper/fig_src/lookflip_frames/<pair_id>/`。PNG 很小，可以提交；推送后把提交号告诉人类。
- 同时复制一份到人类电脑上的 `~/Documents/cvpr2027_fig_frames/`，按 pair_id 分子文件夹，方便在 Claude 桌面端用 "Add folder" 连接。

## 4. 高分辨率展示版（可选，现在不做）
人类和 Claude 选定一对后，如果 255×255 下标号或锚点看不清，再单独决定：用 1 个单卡短作业，从同一快照、同一相机位姿，把选定那一对的 5 个状态按更高分辨率重渲染一份，只用于展示。论文图注写明"为展示以更高分辨率渲染"。这个作业不能占用试跑或主实验的名额。

在 STATUS.md 写一行：导出了哪几对（类别、场景、X 掩码像素数）、仓库路径和本地路径、manifest 的 SHA-256。
