## 需 Claude / 人类决定的判定边界

1. **“无穿模”所需的测量是什么。** 当前列表代理与原位 Teleport helper 都是有限 primitive overlap 检查，接触与穿透深度没有分开，也没有证明所有 MeshCollider/disabled collider 的覆盖。需要明确支持接触如何判、哪些几何范围必须被检查、未知覆盖是否拒绝；不能按 `Col` 名字或统一忽略 Floor/receptacle 来绕过失败。
2. **替代 API 是否足够且可作为测量。** 固定源码的旧 helper 不排除 source trigger，新 helper 排除，但 layer mask 也不同，Teleport 还先赋值 transform、失败后回滚。GarbageCan 的空→拒绝反例说明不能只靠 trigger 解释。应先确定可审计的验证方式及覆盖范围，不能直接批准 `TeleportObject.success` 等价于 `valid_physical`。[固定 helper 源码](https://github.com/allenai/ai2thor/blob/f0825767cd50d69f666c7f282e54abfe58f1e917/unity/Assets/Scripts/UtilityFunctions.cs#L86)、[数组重载与原位检查](https://github.com/allenai/ai2thor/blob/f0825767cd50d69f666c7f282e54abfe58f1e917/unity/Assets/Scripts/PhysicsRemoteFPSAgentController.cs#L661)。Unity overlap 本身包含接触或内部重叠，不能直接提供穿透深度。[Unity API](https://docs.unity3d.com/2020.3/Documentation/ScriptReference/Physics.OverlapCapsule.html)
3. **测量副作用和落定初始化如何处理。** 原位操作后的微小 Euler 变化目前仍严格记录并停止；若考虑数值等价或新的无副作用查询，需明确依据、字段和适用范围，不自行设容差。FP205 的移动初态与下落需要单独定位，不能通过跳过落定检查解决。

任何实现修复都应保持 [METRICS_SPEC §1](../docs/METRICS_SPEC.md) 的完整可移动物体列表、无穿模、编辑物体落定误差 ≤2cm、其他物体位移 ≤1cm、合法 receptacle，以及严格前缀/证据要求。本诊断子步骤交审，尚未提交采用替代判据的新采集；涉及判据或容差调整的决定留给 Claude / 人类。已提交的 T01 A/C 和 T00b 测速继续按原授权运行、监控及记账。旧失败、未完成与未知记录保持原样，不追溯重标。
