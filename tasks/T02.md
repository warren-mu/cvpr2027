# T02 环境接口（D1 已定：实时渲染 + 前缀共用）

**目标**：给 T01v2 的世界对提供统一的环境接口，供评测（T03）和训练（T04 起）使用。
**依赖**：T01v2 试点集通过审查。代码现在就可以写；GPU 运行等试点集通过之后。
**GPU 预算**：不超过 2 GPU·小时。

> 2026-11-08 14:20 重写。原版本按「L / P 两种后端」写，现在 D1 已经定下（见 STATUS.md）。另外，Claude 复查时补上了运行时「证据何时进入输入」的判定；没有这一条，T03 的指标和 T05 的信用分配都无法计算。

## 1. 每个回合都同时运行两个世界
- 每个世界对开**两个** AI2-THOR 控制器，分别从 w0、w1 的快照恢复。智能体的每个动作，同时作用到两个控制器。
- 即使训练臂只用其中一个世界（T0、T2），另一个世界也照样运行，作为「影子世界」，只用来判定证据何时进入输入，不产生训练数据。这样所有臂的证据判定方式完全相同。

## 2. 运行时「证据进入输入」的判定（共享前缀）
- 每一步，两个世界都在相同的 agent 位姿下渲染，同时取实例掩码。
- **只要被编辑的物体（锚点 X）在两个世界的画面里掩码都是 0，这一步就算共享前缀**：智能体收到 w0 渲染的这一帧，两个世界逐字节相同。整帧的最大通道差照常记录（`frame_max_abs_diff`），只作诊断，不作判定依据。
  - 原因：T00b 诊断显示，跨进程渲染和 agent 移动后的相机浮点漂移，会产生与世界内容无关的差异，最大可到 46。如果按整帧像素差来判定，会把这类噪声误当成证据。
- **只要 X 在任一世界的画面里掩码 > 0，证据就进入了输入**：记下这一步为 τ。从这一步起，两个世界各自返回自己渲染的帧，不再共用。
- `info` 里每一步都给出：`shared_prefix`（布尔值）、`tau`（还没到达时为 null）、两个世界中 X 的掩码像素数、`frame_max_abs_diff`。
- 这个判定会写进 METRICS_SPEC，作为「证据进入输入」的正式定义（需要人类确认）。

## 3. 动作、标号与奖励
- 动作：`move <k>`、`turn_left`、`turn_right`、`open <标号>`、`select <标号>`。每回合最多 8 轮，写进 configs，所有方法相同。
- **标号只加在「可见、且离 agent ≤ 1.5 m」的目标类别物体上。** 所以只要能 `select`，就满足 METRICS_SPEC §2 中 SR 的距离和可见条件。
- 奖励：选中的是本世界的正确目标得 1，否则得 0；每个观察动作扣 λ（T04 中 λ = 0.05）。奖励和 SR 完全一致。
- 当前画面没有任何标号时，Q_commit 记为 0（T05 要用）。

## 4. 接入 VAGEN
接入 VAGEN 的环境接口，使 VAGEN 的训练器能直接用这个环境。配对回合的同步推进（T05 §2）在这个接口里实现：共享前缀期间，策略对一份输入只采样一次，同一个动作同时用于两个世界。

## 产出
- 环境代码和单元测试。单元测试至少覆盖：
  - 共享前缀期间，两个世界返回的观测逐字节相同；
  - X 一旦在任一世界可见，就判定 τ，之后两边各自返回自己的帧；
  - 标号只出现在可见且 ≤ 1.5 m 的候选上；
  - 奖励与 SR 一致。
- 用 run_logged 运行，名字 `t02_env_checks`。在 GPU 上回放全部试点世界对的见证动作；报告环境吞吐量（每秒环境步数，含两个世界的渲染）。

## 验收标准
- `audit_provenance.py` 无 FAIL；单元测试全部通过。
- 试点集每一对的见证动作，在两个世界里回放都成功。
- 在 Look 类世界对上，回放见证时记录的 τ，与生成时记录的「第一个观察动作之后出现证据」一致。
- 环境吞吐量至少是模型推理速度的 5 倍；达不到就报告具体数字。
