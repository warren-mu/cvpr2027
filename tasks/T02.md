# T02 环境接口：起点附近视角预渲染 + 查表环境（D1 = P 后端）

**目标**：把每个世界对导出成一张「起点附近视角表」：对表中每个视角，事先在两个世界各渲染一次画面和实例掩码。训练（T04 起）和评测（T03）只查表，不运行仿真器。另外提供建训练池 / 评测集时共用的平衡工具（§7）。
**依赖**：T01v2 试点集通过审查。代码现在就可以写，用 CPU 和手工构造的小视角表测试；GPU 运行等试点集通过之后。
**GPU 预算**：试点集导出和检查不超过 2 GPU·小时。全量导出先按 §5 第 7 项实测的成本估算，超过 20 GPU·小时先报告、等批准。

> 2026-11-08 15:10 重写（人类 15:03 确认 D1 = P）。取代之前「实时渲染 + 前缀共用」的版本。原因：实时双仿真器在训练循环里会遇到黑帧、Unity 崩溃和渲染噪声，两个世界的同步还要改 VAGEN「一个环境一条轨迹」的结构；预渲染把仿真器限制在离线阶段，共享前缀的两个世界拿到的是同一张图。相关指标定义见 METRICS_SPEC §1、§1b（已由人类确认）。

## 1. 视角图
- **状态** = （视点, 朝向），沿用 `pair_core` 的离散 ViewState（8 个朝向，每次转 45°）。起点 s0 =（v0, h0）。
- **观察动作**：与 T01v2 和 METRICS_SPEC §0 相同：`turn_left`、`turn_right`、`move <k>`（移到相邻视点；k 与相对方向文本沿用 T01v2 的 `adjacent_moves` 和 `paired_env` 现有的 Neighbors 文本）。这个任务族没有容器，不提供 `open`。
- **视角图** = 从 s0 出发、不超过 D 个观察动作能到的全部状态。回合最多 D + 1 轮：最多 D 个观察动作，最后一轮必须 `select`。
- **D 的取值**：先按 D = 4 实现。试点导出后，报告「每个世界里能看到 X 的一步动作」中转头和移动各占多少，以及 §5 第 1 项中 `min_solution_turns` 的分布。D 由人类确认后写进 configs，并在 T03 评测集冻结之前冻结。
- 两个世界的视角图必须完全相同：每个状态的可走相邻视点和方向文本，在 w0、w1 中一致。如果锚点 X 挡住某个视点导致不一致，丢弃这一对，原因记为 `graph_mismatch`。

## 2. 导出（每个世界对一个作业单元）
在**同一个进程**里，对视角图中的每个状态 s：
1. agent 放到状态 s 的位姿，在 w0 中渲染 RGB 和实例掩码；
2. agent 不动，用快照中的完整位姿列表切到 w1，再渲染一次；
3. 记录 X、A、B 在两个世界的掩码像素数，以及两帧的最大通道差 `frame_max_abs_diff[s]`。

每个状态都切换一次世界，对应 T00b 诊断里最接近逐像素一致的条件 E（同一进程、agent 不动）。如果有更快、并且能证明两个世界的相机位姿逐位相同的做法，先报告再用。

**状态分类**（METRICS_SPEC §1b）：
- **共享状态**：X 在两个世界的掩码都为 0，且 `frame_max_abs_diff[s] ≤ 3`。两个世界都使用 w0 渲染的同一张图，只存一份。
- **分叉状态**：X 在至少一个世界的掩码 > 0。两个世界各用自己渲染的图。
- **其他情况**：X 在两个世界都不可见，但两帧差异 > 3（例如 X 的影子、反光）。这样的状态只要在视角图里出现，就丢弃整对，原因记为 `non_anchor_divergent`，报告比例（METRICS_SPEC §1「无锚点泄露」）。

**标号与文本**：
- 标号只加在 `success_eligible` 的候选上（可见、且离 agent ≤ 1.5 m），与 METRICS_SPEC §2 一致。注意：现有 `public_selectable` 不判距离，不能单独用来决定加不加标号，否则远处候选也会带标号，奖励就不再等于 SR，Q_commit 的归一化范围也会变。
- 共享状态下，标号和文本都从 w0 的数据生成，两个世界逐字节相同。
- **标号编号**：每对随机分配，种子由 pair_id 决定，与 A、B 的角色无关，两个世界相同。

## 3. 两个时刻（METRICS_SPEC §1b）
- **τ** = 回合中第一次到达分叉状态的步号。在此之前，两个世界的全部输入（图像和全部文本）逐字节相同。Look 类的 s0 是共享状态，所以 τ ≥ 1；直接类的 s0 是分叉状态，τ = 0。
- **τ_seen** = 回合中第一次到达「本世界 X 掩码 ≥ 250 像素」的状态的步号。过早承诺、证据后更新准确率、T05 中 T4 一致性项的施加条件，都按 τ_seen。
- 两个时刻都只由智能体自己走过的状态序列和预先算好的状态表决定。只用单个世界训练的臂（T0、T2）也得到完全相同定义的 τ 和 τ_seen，不需要运行另一个世界。

## 4. 回合、奖励、info
- `reset(pair_id, world)` 返回 s0 的观察；`step(动作)` 查表得到下一个状态。
- 每个观察动作扣 λ（T04 中 λ = 0.05）。`select <标号>` 结束回合：选中本世界的正确目标得 1，否则得 0。只有带标号的候选可选，所以选中即满足 METRICS_SPEC §2 的 SR 条件，奖励与 SR 完全一致。
- 到第 D + 1 轮仍未 `select`，回合结束，奖励 0，观察扣分照常。无法解析的输出算作一轮，不改变状态；所有臂规则相同。
- `info` 每一步给出：
  - `state_id`、`shared`、`tau`（未到达时为 null）、`x_seen_step`（未看到时为 null）；
  - 两个世界中 X 的像素数、`frame_max_abs_diff`；
  - 当前可选标号列表（T05 计算 Q_commit 要用）。
- 实现成 `paired_env.py` 中 `ObservationBackend` 的一个后端（查表后端）。`paired_env.py` 开头那句「从不把一个世界的像素给另一个世界用」改为：只有经过 §2 检查的共享状态，才把 w0 的图同时给两个世界。

## 5. 检查（用 run_logged 运行，名字 `t02_viewsets_pilot`）
对试点集的每一对：
1. **可解性**（METRICS_SPEC §1，已由人类确认）：
   - 在视角图上复核 T01v2 补充 4 的 (a)：每个世界都有一步观察动作能看到 X（≥ 250 像素）。结果必须与 T01v2 的记录一致。
   - 用广度优先搜索计算 `min_solution_turns`：两个世界共用同一段动作，直到第一次到达分叉状态；之后各自走到能看到 X（≥ 250 像素）的状态，再到正确目标带标号的状态 `select`。取两个世界中较大的总轮数，在所有共同前缀中取最小值。
   - 要求 `min_solution_turns ≤ D + 1`，不满足的丢弃，原因记为 `not_solvable_within_budget`。直接类只要求在 D + 1 轮内能 `select` 正确目标。
2. **起点与首步**：
   - Look 类的 s0 在导出中仍是共享状态，T01v2 记录的共同首步观察动作到达的是分叉状态；
   - 直接类的 s0 是分叉状态，且 X 在两个世界的 s0 掩码都 ≥ 250。
3. **见证回放**：T01v2 的见证在查表环境里回放，两个世界都成功（只针对长度 ≤ D + 1 的见证）。
   - `select` 按物体名换算成本环境的标号；
   - 移动按目标视点换算成本环境的 `move <k>`，不按 T01v2 记录里的编号。T01v2 的 `inverse_action` 把回退一律写成 `move 1`，按编号回放会误报失败。
4. **前缀复用合法**（`prefix_verified_identical`）：每个共享状态都有同进程两次渲染的记录，最大通道差 ≤ 3，X 掩码在两个世界都为 0。
5. **缓存与实时一致**（`cache_matches_live`，METRICS_SPEC §1）：随机抽 ≥ 200 个（对, 状态），在新进程里分别从两个世界的快照恢复、各重新渲染一次。X、A、B 中凡在任一次渲染里掩码 > 0 的，像素数相差不超过 2% 或 10 个像素（取较大者），且掩码 IoU ≥ 0.9；共享 / 分叉分类和标号集合不变。整帧像素差只作诊断记录。任何一个抽样状态不通过，停下报告，不进入训练。
6. **吞吐**：查表环境每秒步数。
7. **导出成本**：每对的状态数、每对导出耗时、每对存储量。按 1400 对估算全量导出的 GPU·小时和存储。

**报告**：
- 共享 / 分叉状态数的分布；
- 各类丢弃原因：`graph_mismatch`、`non_anchor_divergent`、`not_solvable_within_budget` 等；
- §1 中关于 D 的两项统计；
- §7 的平衡统计；
- 第 7 项的成本估算。

## 6. 单元测试（CPU，手工构造的小视角表）
- 共享状态下，两个世界返回的图像和文本逐字节相同；到达分叉状态的那一步记为 τ，此后各自返回自己的图。
- 回到共享状态（例如转回 s0）时，两个世界再次拿到同一张图，τ 不变。
- `x_seen_step` 只在本世界 X ≥ 250 像素时记录；只看到「A 旁边没有 X」时不记录。
- 标号只出现在可见且 ≤ 1.5 m 的候选上；标号编号与 A、B 角色无关。
- 奖励与 SR 一致；超过 D + 1 轮奖励为 0；观察扣分正确。
- `min_solution_turns` 在手工例子上与手算一致。

## 7. 训练池 / 评测集的平衡工具（T03、T04 建集时都用这一个函数）
T01v2 的构造顺序有偏差（见 T01v2 补充 5）：Flip 对的 w0 总把 X 放在按名字排第一的候选 a 旁边，Stay 对多数在 a 一侧。这会让「不看锚点、记住这个场景选哪个」也能做对。建集时这样处理：
1. Flip 对：按 pair_id 决定的种子，以 1/2 的概率交换 w0 和 w1 的标签。两个世界本来就都是构造出来的，标签本身没有含义。
2. Stay 对：在每个场景内，让 X 在 a 一侧和 b 一侧的对数相等，多的一侧随机下采样。
3. 报告：按场景、按类别，在 r = 0.5 下正确目标是 a 的回合比例；s0 画面中 r = 0.5 下正确目标在左半边的比例。全集两个比例都要在 0.4–0.6；单个场景超出 0.3–0.7 的列出来。
